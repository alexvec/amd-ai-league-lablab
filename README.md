# Trailmark

Ask for one fact from the web. Trailmark goes to the page, answers, and shows the quote behind every claim. A plain program checks that each quote is really on the page that was fetched. A claim that fails is removed from the answer.

- **Live:** https://amd-ai-league-lablab.vercel.app
- **Entry:** AMD AI League on lablab.ai, Match 4, Intelligent Web Information Retrieval. Trailmark is a working name. Not submitted, and no evaluator has accepted it.

The intended engine is an open-weight model served on ROCm, doing the planning, link choice and claim writing. That part of the entry depends on a run that has not happened yet. No benchmark, accuracy or usage figure exists, so none is given.

## How it works

1. **Find pages.** Start from a given URL, a URL in the question, or a Wikimedia search of English Wikipedia.
2. **Read and navigate.** Fetch through a guarded fetcher, extract readable text, store a snapshot with its SHA-256, and follow links.
3. **Draft claims.** A backend proposes claims, each with a quote and a source URL. Backends cannot mark anything verified.
4. **Verify.** `trailmark/verifier.py` checks each quote against the stored text of a page fetched in this run. It accepts exact matches and whitespace-normalised matches. It never folds case or fuzzy-matches. Any number in a claim must also occur in its quote.
5. **Assemble.** The answer is built only from claims that passed. The LLM backend gets bounded retries on failures.

The verifier proves the words were on the fetched page. It does not prove that the quote supports the claim, or that the page is true.

Backends are chosen by environment variable, and every response and trace records which one produced it.

| Variable | Meaning |
|---|---|
| `TRAILMARK_BACKEND` | `extractive` (default), `llm` or `replay` |
| `TRAILMARK_LLM_BASE_URL`, `TRAILMARK_LLM_MODEL`, `TRAILMARK_LLM_API_KEY` | OpenAI-compatible server for `llm` |
| `TRAILMARK_REQUEST_SECONDS` | Per-request time limit, default 25 |

A backend is labelled `rocm-*` only when a ROCm tool on the machine reports a GPU and the model server is on loopback. No setting can force that label.

## Run it locally

Requires Python 3.12.

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m uvicorn trailmark.server:app --port 8000
```

Open http://127.0.0.1:8000. No account or key is needed.

```bash
curl -s http://127.0.0.1:8000/health
curl -s http://127.0.0.1:8000/ask -H 'content-type: application/json' \
  -d '{"question":"What does the key word MUST mean?","start_url":"https://www.rfc-editor.org/rfc/rfc2119.html"}'
```

## API

- `POST /ask` takes `{"question": "...", "start_url": "..."}`, with `start_url` optional, and returns `answer`, `sources`, `claims` with a `verified` flag on each, `snapshots` and `trace`. Add `"mode": "replay"` and an optional `"trace_id"` to replay a recorded run.
- `GET /health` returns the active backend, model, deployment and AMD status.
- `GET /traces` lists the recorded runs.

The field names live in `trailmark/api_schema.json`, so they can change without touching the core. The official Match 4 schema is unverified. See [docs/competition.md](docs/competition.md).

## Safety on the public endpoint

The endpoint fetches URLs supplied by strangers, so `trailmark/netguard.py` and `trailmark/fetcher.py` apply these rules:

- Only `http` and `https`, only ports 80 and 443, and no credentials in URLs.
- Private, loopback, link-local, metadata, reserved and numeric-form hosts are refused. The check runs after DNS resolution and again on every redirect. The connection then goes to the checked address, so DNS rebinding cannot move it.
- Caps per request, from `trailmark/config.py`: 5 pages, 40 steps, 4 redirects per fetch, 2 MB per response including after gzip, 25 seconds overall. The deadline is enforced by shutting the socket, so a slow sender cannot outlast it.
- `robots.txt` is respected on every hop, with a pause between requests to the same host. An unreachable `robots.txt` counts as denied.
- Fetched text reaches the page only through text nodes, under a strict Content Security Policy.
- For the LLM backend, page contents are fenced as untrusted data, and a page cannot close the fence. The model picks links only by index from a list built by the code. Its claims still have to pass the verifier.

Limits of this: the rate limit is per serverless instance, so it is best effort. JavaScript-heavy sites are best effort too, since no browser is used for fetching. Login walls, CAPTCHAs and paywalls are out of scope.
